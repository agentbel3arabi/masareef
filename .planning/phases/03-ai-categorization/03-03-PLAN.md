    1. Create `backend/app/services/categorization.py`:

       **categorize_transactions(session, household_id, transaction_ids):**
       - Load transactions by IDs with `WHERE household_id = household_id AND id IN transaction_ids AND is_active = True`
       - Load available categories via `category_service.list_categories(session, household_id, assignable=True, page_size=200)`
       - Build `available_categories` list: `[{"id": c.id, "name_en": c.name_en} for c in cats]`
       - For each transaction:
         - Call `apply_rule_engine(session, household_id, tx.description)` then if match, update tx.category_id, tx.ai_categorized=True, tx.ai_confidence=confidence, append CategorizationResult(source="rule")
       - Collect unmatched transactions
       - If unmatched and `check_budget(session, household_id)` is True:
         - Load `settings = Settings()`, get `AI_MODEL`, `AI_BATCH_SIZE`, `AI_MAX_CONCURRENCY`
         - Process unmatched in batches of `AI_BATCH_SIZE`:
           - Call `suggest_categories_batch(batch_txs_dicts, available_categories, settings.AI_MODEL, settings.AI_MAX_CONCURRENCY)`
           - For each result: if suggestion is not None, update tx.category_id, tx.ai_categorized=True, tx.ai_confidence=suggestion.confidence, record_usage with estimated tokens (~500 per call)
           - If suggestion is None: leave tx uncategorized, append CategorizationResult(source="uncategorized")
       - If budget exhausted: all unmatched get source="uncategorized"
       - `await session.flush()`
       - Return list of CategorizationResult

       **apply_correction(session, household_id, transaction_id, category_id):**
       - Load transaction: `SELECT ... WHERE id = transaction_id AND household_id = household_id AND is_active = True`
       - If not found, raise ValueError("Transaction not found")
       - Update: `tx.category_id = category_id`, `tx.ai_categorized = True`, `tx.ai_confidence = 1.0`
       - Extract merchant: `merchant = extract_merchant_name(tx.description or "")`
       - If merchant is not empty: `await upsert_rule(session, household_id, merchant, "contains", category_id, confidence=1.0)`
       - `await session.flush()`

       **approve_batch(session, household_id, transaction_ids):**
       - Load transactions: `SELECT ... WHERE id IN transaction_ids AND household_id = household_id AND ai_categorized = True AND is_active = True`
       - For each: `tx.ai_confidence = 1.0` (mark as user-confirmed, no rule creation per D-09 / RESEARCH.md Open Question #3)
       - `await session.flush()`
       - Return count of approved

       **categorize_batch_background(batch_id: str, household_id: str):**
       - Create fresh session: `async with async_session_factory() as session:`
       - Load uncategorized transactions: `SELECT ... WHERE import_batch_id = UUID(batch_id) AND household_id = UUID(household_id) AND category_id IS NULL AND is_active = True`
       - If none, return
       - Call `categorize_transactions(session, UUID(household_id), [tx.id for tx in txs])`
       - `await session.commit()`
       - Log: `logger.info("Batch categorization complete for batch=%s, household=%s", batch_id, household_id)`
       Note: This function is `async def` and creates its own session (RESEARCH.md Pitfall 1 — never reuse request session in background tasks).

           data: BatchCategorizationRequest,

| Boundary | Description |

| client to categorize-batch | User-supplied transaction IDs cross boundary — must validate ownership |
| import to background task | Background task runs after response; must create own DB session |
| service to LLM | Transaction descriptions sent to external provider |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-3-01 | Spoofing | categorization.py service | mitigate | All transaction queries include `WHERE household_id = :hid`; user cannot categorize transactions from other households |
| T-3-07 | Tampering | approve-batch | mitigate | Validate transaction_ids belong to household before updating; only set ai_confidence, not category_id |
| T-3-08 | Repudiation | correct endpoint | accept | Correction overwrites previous category; no audit trail in v1 — acceptable for MVP |
| T-3-09 | Denial of Service | categorize-batch | mitigate | Budget guard limits LLM calls per household; batch size capped by AI_BATCH_SIZE config |
</threat_model>
