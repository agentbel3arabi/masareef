# Phase 1 -- UI Design Contract

> Visual and interaction contract for Phase 1: Stabilization. This phase adds no new UI -- it documents the existing design system state so frontend tests can verify visual contracts against established patterns. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

| Property | Value |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing, button internal gaps |
| md | 16px | Default element spacing, card padding |
| lg | 24px | Section padding, card body spacing |
| xl | 32px | Layout gaps between major sections |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions: Button touch targets use Tailwind height utilities (h-6 through h-9 = 24px through 36px). Icon-only buttons use square sizing (size-6 through size-9). These are smaller than the 44px touch target recommendation because this is a desktop-first application; mobile touch targets will be addressed in Phase 7 polish.

**Test verification:** Tests should confirm components render without layout overflow. No pixel-perfect spacing assertions needed -- Tailwind utility classes handle spacing.

## Typography

|------|------|--------|-------------|

Font stack: `var(--font-inter), var(--font-noto-arabic), system-ui, sans-serif` defined in `globals.css` as `--font-sans` and `--font-heading`.

**Test verification:** Tests should assert text content renders correctly. Do not test computed font sizes -- trust Tailwind classes. Test that `font-sans` CSS variable resolves (verifies font loading setup).

## Color

All colors are defined as HSL CSS variables in `globals.css` `@layer base`. Both light and dark mode tokens exist.

| Role | Light Mode HSL | Dark Mode HSL | Usage |
|------|---------------|---------------|-------|
| Dominant (60%) -- background | `0 0% 100%` (#FFFFFF) | `222.2 47.4% 11.2%` (#0F172A) | Page background |
| Secondary (30%) -- surface | `210 40% 98%` (#F8FAFC) | `217.2 32.6% 17.5%` (#1E293B) | Cards, sidebar, elevated panels |
| Accent (10%) -- primary | `142.1 76.2% 36.3%` (#16A34A) | `142.1 76.2% 36.3%` (#16A34A) | See reserved-for list below |
| Destructive | `0 84.2% 60.2%` (#EF4444) | `0 84.2% 60.2%` (#EF4444) | Delete buttons, error messages, expense amounts |
| Warning | `37.7 92.1% 50.2%` (#F59E0B) | `37.7 92.1% 50.2%` (#F59E0B) | Budget alerts, due-soon warnings |

**Accent (primary green #16A34A) reserved for:**
- Primary CTA buttons (default variant)
- Income/positive amounts
- Success states and toast checkmarks
- Focus ring (`--ring`)
- Sidebar active item highlight
- Chart series 1

**Test verification:** Tests should verify that destructive buttons use the `destructive` variant class. Tests should verify theme toggle switches between light/dark by checking `document.documentElement` class. Do not assert exact hex values in component tests.

## Copywriting Contract

Phase 1 adds no new UI copy. This section documents existing patterns that tests should verify:

| Element | Copy Pattern |
|---------|-------------|
| Primary CTA (accounts) | "Add Account" / "اضافة حساب" |
| Empty state heading | Context-specific (e.g., "No accounts yet") |
| Empty state body | Instruction + CTA (e.g., "Add your first account to start tracking") |
| Error state | Problem + solution: "Something went wrong. Please try again." |
| Destructive confirmation | AlertDialog pattern: title states action, description states consequence, Cancel + Confirm buttons |
| Toast success | Sonner toast with green checkmark |
| Toast error | Sonner toast with red icon |

**Test verification:** Tests should verify that key copy strings render. Use `screen.getByText()` or `screen.getByRole()` with accessible names. Tests must work with both Arabic and English -- use i18n keys or test both locales.

## RTL Contract

All CSS uses logical properties exclusively per CLAUDE.md rule 4:

| Forbidden | Required Equivalent |
|-----------|-------------------|
| `pl-`, `pr-` | `ps-`, `pe-` |
| `ml-`, `mr-` | `ms-`, `me-` |
| `left-`, `right-` | `start-`, `end-` |
| `text-left`, `text-right` | `text-start`, `text-end` |
| `border-l-`, `border-r-` | `border-s-`, `border-e-` |
| `rounded-l-`, `rounded-r-` | `rounded-s-`, `rounded-e-` |

**Test verification:** Tests do not need to verify RTL rendering directly (jsdom does not compute layout direction). The CI lint step and code review enforce logical properties. If a grep-based lint rule is added during this phase, it should scan for forbidden physical directional classes.

## Phase-Specific Testing Guidance

Since Phase 1 is stabilization, the UI-SPEC serves as the reference for what frontend tests should verify:

### Priority 1: Utility Functions (pure logic, no rendering)
- `formatAmount` -- all 7 supported currencies, edge cases (zero, negative, large values)
- `parseAmountMinor` -- string parsing with currency exponent
- `cn()` -- class merging behavior

### Priority 2: UI Components (render + interaction)
- Button -- all 6 variants render, click handler fires, disabled state prevents clicks
- Card -- compound component renders header/content/footer
- Dialog -- opens on trigger, closes on action, renders title and content
- AlertDialog -- confirmation flow: trigger opens, cancel closes without action, confirm fires callback

### Priority 3: Layout Components
- AppShell -- renders sidebar and main content
- Navbar -- renders navigation items
- ThemeToggle -- toggles between light and dark

### Priority 4: Hooks and Providers (with mocked API)
- TanStack Query hooks require QueryClientProvider wrapper
- Auth hooks require mocked Supabase client
- Test loading, success, and error states
