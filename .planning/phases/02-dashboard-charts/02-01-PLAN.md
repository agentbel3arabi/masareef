**Create `backend/app/services/dashboard.py`** with these functions:

1. `get_income_vs_expenses(session, household_id, *, months=6, base_currency="EGP")`:
   - Compute start_date = today - relativedelta(months=months), floored to 1st of month
   - Query: `SELECT currency, strftime('%Y-%m', date) as month, SUM(CASE WHEN amount_minor > 0 THEN amount_minor ELSE 0 END) as income, SUM(CASE WHEN amount_minor < 0 THEN ABS(amount_minor) ELSE 0 END) as expenses FROM transactions WHERE household_id=? AND is_active=True AND transfer_id IS NULL AND date >= start_date GROUP BY currency, month`
   - IMPORTANT: Use `func.strftime('%Y-%m', Transaction.date)` NOT `date_trunc` — tests use SQLite which lacks `date_trunc`. See Research Pitfall 5.
   - After query: group results by month. For each month, collect per-currency amounts into a dict, call `fx.convert_to_base(session, income_by_currency, base_currency)` and `fx.convert_to_base(session, expense_by_currency, base_currency)` to get converted totals.
   - Return `list[IncomeVsExpensesMonth]` sorted by month ascending.

2. `get_spending_by_category(session, household_id, *, base_currency="EGP")`:
   - Query current month expenses grouped by category_id and currency: `WHERE amount_minor < 0 AND transfer_id IS NULL AND is_active = True AND date >= month_start AND date <= today`
   - Join Category table to get `name`, `name_ar`, `color` fields
   - Convert each category's per-currency totals to base_currency via `fx.convert_to_base`
   - Sort by absolute amount descending, take top 8, aggregate rest into "Other" (category_id=None, name="Other", name_ar="أخرى")
   - Compute percentage = (category_amount / total_amount) * 100 for each
   - Return `list[SpendingByCategory]`

3. `get_net_worth_trend(session, household_id, *, months=6, base_currency="EGP")`:
   - For each month in range (oldest to newest):
     - **Accounts component**: Query all active accounts. For each account, compute balance at month_end = `account.balance_minor + SUM(transactions WHERE account_id=account.id AND date <= month_end)`. Group by currency, convert to base.
     - **Debts component**: Query active debts. For each debt, compute remaining at month_end. Simple approach: `remaining = principal_minor - SUM(debt_payments WHERE debt_id=debt.id AND payment_date <= month_end)`. Group by currency, convert to base.
     - Use Python-side month bucketing, NOT `date_trunc` (SQLite compatibility per Pitfall 5).
     - Performance: Pre-fetch all transactions for the household in the date range with a single query. Pre-fetch all debt payments. Then compute month-by-month in Python.
   - net_worth_minor = accounts_minor - debts_minor
   - Return `list[NetWorthTrendPoint]`

4. `get_stat_cards(session, household_id, *, base_currency="EGP")`:
   - Compute 4 stat cards with month-over-month trends:
   - **Net Worth**: Use existing `compute_net_worth` pattern — query all active accounts, group balances by currency, convert to base. For previous month: subtract current month's transactions from each account balance. Compute trend: `direction = "up" if current > previous else "down" if current < previous else "flat"`. `absolute_delta = abs(current - previous)`. `percentage = abs(current - previous) / abs(previous) * 100 if previous != 0 else None`.
   - **Spending This Month**: SUM(ABS(amount_minor)) WHERE amount_minor < 0 AND transfer_id IS NULL, current month. Previous month same query. Trend computed same way. For spending, down means less spending.
   - **Active Debts**: COUNT debts WHERE status='active' AND is_active=True. value_minor = SUM of remaining balances (principal_minor - paid_amount) converted to base currency. Previous month: same count at previous month end (approximate: same query, debts active then). Trend on remaining total.
   - **Upcoming Payments (next 30 days)**: Query active debts with `payment_day_of_month`. For each: compute next payment date. If next payment is within 30 days, include `monthly_payment_minor`. Also query active installments with `payment_day_of_month`. Also query P2P splits where `paid = false` and `due_date` within 30 days (if due_date column exists on p2p_debt_split). Sum all upcoming payments converted to base currency. `count` = number of upcoming payment items.
   - Return `StatCardsData`
