## A1. Category Dropdown Shows `__uncategorized__` After Selection

**Files:** `transaction-form.tsx`, `transaction-row.tsx`

**Root cause:** When `categoryId === ""` (uncategorized selected), `selectedCategory` resolves to `undefined`. The code falls through to `<SelectValue placeholder={t("transactions.uncategorized")} />`. However, `<SelectValue>` renders the current Select **value** (the raw string `"__uncategorized__"`) when a value is set — the `placeholder` prop only shows when no value exists.

**Fix:** Add an explicit branch for `categoryId === ""` that renders the translated label directly, before the `<SelectValue>` fallback.

In `transaction-form.tsx` (lines 167-177), change the SelectTrigger content:
```tsx
<SelectTrigger className="w-full">
  {selectedCategory ? (
    <span className="flex items-center gap-2">
      <CategoryIcon icon={selectedCategory.icon} className="h-4 w-4 shrink-0" />
      {locale === "ar" && selectedCategory.name_ar
        ? selectedCategory.name_ar
        : selectedCategory.name_en}
    </span>
  ) : (
    <span>{t("transactions.uncategorized")}</span>
  )}
</SelectTrigger>
```

In `transaction-row.tsx` (lines 287-305), same pattern — the IIFE already handles `selectedCategory` but falls through to `<SelectValue>` for the uncategorized case:
```tsx
if (selectedCategory) {
  return (
    <span className="flex items-center gap-2">
      <CategoryIcon icon={selectedCategory.icon} className="h-4 w-4 shrink-0" />
      {locale === "ar" && selectedCategory.name_ar
        ? selectedCategory.name_ar
        : selectedCategory.name_en}
    </span>
  );
}
return <span>{t("transactions.uncategorized")}</span>;
```

**Acceptance:** Selecting "Uncategorized" in the category dropdown displays the translated label, never the raw `__uncategorized__` string.

## B1. Debt Detail Action Buttons to Navbar

**Files:** `loan-detail-content.tsx`, `p2p-detail-content.tsx`

**Current state:** Both detail pages render "Record Payment" and "Mark as Paid" (and "Reactivate" for paid-off debts) as inline `<Button>` elements inside a `<div className="flex flex-wrap gap-3">` in the page body. Every other page in the app uses `useNavbarActions` to place action buttons in the top navbar.

**Fix:**

1. Import `useNavbarActions` from `@/contexts/navbar-actions-context`
2. Add a `useEffect` that calls `setActions(...)` with the action buttons
3. Style buttons as `variant="outline" size="sm"` with icons:
   - Record Payment: `<CreditCard className="h-4 w-4 me-1" />` + text
   - Mark as Paid: `<CheckCircle className="h-4 w-4 me-1" />` + text
   - Reactivate: `<RotateCcw className="h-4 w-4 me-1" />` + text (already has icon)
4. Remove the inline `<div className="flex flex-wrap gap-3">` action section from the page body
5. Clean up on unmount: `useEffect(() => () => setActions(null), [setActions])`
6. Update actions when `debt.status` changes (active vs paid_off)

**loan-detail-content.tsx specifics:**
- Active debt: Record Payment + Mark as Paid
- Paid-off debt: Reactivate
- Record Payment handler includes schedule prefill logic — preserve this in the navbar button's onClick

**p2p-detail-content.tsx specifics:**
- Record Payment (always visible) + Mark as Paid (only when active)
- Mark as Paid uses inline `markPaid.mutate()` with `disabled={markPaid.isPending}` — preserve loading state

**Acceptance:** Debt detail pages show action buttons in the top navbar with consistent icon + text styling. No inline action buttons in the page body.

## E1. Inline Form Validation

**Files:** All form components: `create-account-dialog.tsx`, `transaction-form.tsx`, `transfer-form.tsx`, `bank-loan-form.tsx`, `p2p-debt-form.tsx`, `installment-form.tsx`, `person-form.tsx`, `record-payment-form.tsx`

**Current state:** Forms rely on backend 400 responses for validation. No client-side validation feedback.

**Approach:** Simple required-field validation on submit. No complex validation library needed.

1. Add a `touched` or `submitted` state boolean, set to `true` on first submit attempt
2. When `submitted` is `true`, show red inline error text below empty required fields
3. Block form submission if any required field is empty
4. Use a shared inline error component or just conditional `<p className="text-sm text-destructive">` text
5. Required fields are already marked with `<RequiredLabel required>` — validation aligns with those markers

**Required fields per form:**
- **Account form**: name, type, currency, balance
- **Transaction form**: amount, date, account (when no accountId prop)
- **Transfer form**: from account, to account, amount, date
- **Bank loan form**: name, principal, rate, term, start date, currency
- **P2P debt form**: person, direction, amount, currency
- **Installment form**: merchant, total amount, monthly amount, months, start date, currency, linked account
- **Person form**: name
- **Record payment form**: amount, date

**Error message:** Use a single i18n key `"common.required"` = "This field is required" / "هذا الحقل مطلوب"

**Acceptance:** Submitting a form with empty required fields shows inline red error text below each empty field. Form does not submit until all required fields are filled.
