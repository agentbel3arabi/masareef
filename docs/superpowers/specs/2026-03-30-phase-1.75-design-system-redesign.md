# Phase 1.75: Design System & Page Redesign — Design Spec

> **Phase position:** Between Phase 1.5 (Gap Remediation) and Phase 2 (Import & Templates).
> Unit 1.5M (workflow/docs) completes first, then Phase 1.75 begins.

---

## 1. Problem Statement

The current frontend pages were built functionality-first across Phase 1 and Phase 1.5. While all features work correctly, the pages don't consistently match their Stitch design references. The existing Stitch project (`3967836651870677827`) was generated with an incorrect logo and tagline. Additionally, there's no shared component library or design playbook to ensure consistency across the remaining 19 phases.

### Specific Gaps

- **Branding:** Stitch designs use a generated logo/tagline instead of the real Masareef brand
- **Page fidelity:** Accounts, Transactions, Account Detail, Dashboard, and Transfers pages don't match their Stitch designs (Wave 6 deferred items #15, #16, #17, #18)
- **Floating Action Button (FAB):** Not properly implemented on the transactions page
- **Sidebar:** Needs full Stitch redesign (current version was a quick fix in Wave 6)
- **Design consistency:** No shared component library — each page implements its own card, table, filter, and form patterns
- **No playbook:** Future phases have no documented process for generating and implementing designs consistently

## 3. Branding

### Taglines (configurable via `brand.ts` + i18n)

- **English:** "Your entire financial life, finally making sense."
- **Arabic:** "حسبة بيتك، متظبطة بالملي."

### Brand Config

A single source of truth at `frontend/src/config/brand.ts`:

```typescript
export const BRAND = {
  name: "Masareef",
  nameAr: "مصاريف",
  tagline: "Your entire financial life, finally making sense.",
  taglineAr: "حسبة بيتك، متظبطة بالملي.",
  url: "https://masareef.app",
} as const;
```

These values also flow into `messages/en.json` and `messages/ar.json` so all components use `t('brand.tagline')` instead of hardcoded text. Changing the tagline in one place updates it site-wide.

### Logo Usage

Logo files exist at `logos/svg/` in three variants:
- **Default** (`transparent/horizontal-transparent.svg`): Green gradient icon + black text — for light backgrounds
- **White** (`transparent/horizontal-transparent-white.svg`): Green gradient icon + white text — for dark/colored backgrounds
- **Icon only** (`transparent/icon-transparent.svg`): Green gradient icon — for small spaces

The `Logo` component accepts a `variant` prop (`"default" | "white"`) to select the right file.

### Auth Marketing Panel

- **Background:** Dark navy `#0F172A` (not green — the green gradient icon blends into green backgrounds)
- **Logo:** White variant (`horizontal-transparent-white.svg`) — green icon pops against dark navy, white text is legible
- **This was validated visually** using the actual SVG logos on different backgrounds

### Stitch MCP as Primary Tool

**Hard requirement:** All design work uses Stitch MCP tools (`generate_screen_from_text`, `edit_screens`, `get_screen`, `get_project`, `list_screens`). Static HTML files in `docs/stitch-designs/html/` are fallback only when MCP is unavailable.

### User Design Review Gate

**Hard requirement:** Every Stitch-generated screen must be reviewed and approved by the user before implementation begins. The workflow per screen is:

```
1. Generate screen via Stitch MCP (generate_screen_from_text / edit_screens)
2. Present to user for review (share screenshot or Stitch project link)
3. User reviews and either:
   a. Approves → proceed to implementation
   b. Requests changes → revise via Stitch MCP (edit_screens), return to step 2
4. Only after approval: implement the page using shared components
```

No page implementation starts without explicit user sign-off on the Stitch design.

## 9. "Coming Soon" Policy & Backend Dependency Tracking

### Policy

Stitch designs may include UI elements (buttons, tabs, pages, charts) that require backend endpoints or features not yet implemented. These elements are **not skipped** — they are implemented visually with a clear disabled/"coming soon" state:

- **Buttons:** Rendered but disabled with a tooltip: "Coming soon"
- **Tabs/sections:** Shown in the UI but content area displays an empty state with "Coming in Phase N"
- **Charts:** Placeholder cards with the chart title and a "Coming in Phase 4" message
- **Forms with missing API:** Form UI is built, submit is disabled, note explains what's pending

This ensures the full Stitch design is reflected in the UI, users can see what's coming, and nothing is silently omitted.

### Backend Dependency Tracker

A running file at `docs/superpowers/plans/phase-1.75/backend-dependencies.md` tracks every backend requirement discovered during Phase 1.75 implementation. Format:

```markdown
# Phase 1.75: Backend Dependencies

Discovered during page redesign. Each item maps to a future phase.

| # | UI Element | Page | Backend Needed | Target Phase | Status |
|---|-----------|------|---------------|-------------|--------|
| 1 | Net worth trend chart | Dashboard | GET /api/v1/net-worth/history | Phase 4 | Pending |
| 2 | Reconcile button | Account Detail | POST /api/v1/accounts/{id}/reconcile | Phase 2+ | Pending |
| ... | ... | ... | ... | ... | ... |
```

This file is:
- **Updated during implementation** — every time we encounter a Stitch design element that needs backend work
- **Reviewed at phase end** — to confirm all items are mapped to a roadmap phase
- **Input for future phase planning** — Phase 2+ planners check this file for any backend work the redesign surfaced

### Language Strategy

**Stitch screens are generated in English.** Stitch AI produces higher quality layouts and text in English. During implementation, all code uses **RTL-first CSS logical properties** (`ps-`, `pe-`, `start-`, `end-`, never `pl-`, `pr-`, `left-`, `right-`) and Arabic rendering is verified as part of every wave's acceptance criteria. This is a pragmatic adaptation of the project's "Arabic first" principle — the design layout is the reference, the implementation is RTL-first.

### Prompt Template for Screen Generation

Every screen prompt must include:
- The Masareef logo is a green gradient icon (teal #0D9488 to emerald #16A34A) showing a stylized chart with a circular node
- Tagline EN: "Your entire financial life, finally making sense."
- Specific page content and layout requirements
- Reference to the feature spec for data/behavior accuracy
