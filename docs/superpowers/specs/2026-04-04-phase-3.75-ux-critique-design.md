## 1. Backend

### 1A — Tech Debt Fixes

#### BL-030: Async JWKS Cache

**File:** `backend/app/dependencies.py`

Replace synchronous `httpx.get()` in the JWKS cache retrieval path with `httpx.AsyncClient`. The current implementation blocks the event loop on cache miss.

**Fix:**
- Use `httpx.AsyncClient` for JWKS fetching
- Maintain the existing cache-first pattern (only fetch on miss/expiry)
- Ensure the async client is properly closed or uses a context manager

#### BL-031: FX Transfer Integer Arithmetic

**File:** `backend/app/services/transfer.py`

Replace float division in FX transfer amount computation with integer arithmetic using the 10,000 scale factor.

**Fix:**
- Current: `target_amount = source_amount * rate / 10000` (float division)
- New: `target_amount = (source_amount * rate) // 10000` (integer division)
- Verify rounding behavior matches expectations (round toward zero)
- Add a test case comparing old float result vs new integer result for representative amounts

### 1B — Transaction Summary Endpoint

**New endpoint:** `GET /api/v1/transactions/summary`

Single flexible endpoint serving both the dashboard (monthly spending) and the transactions page (period totals with active filters).

**Query parameters:**
| Param | Type | Default | Description |
|-------|------|---------|-------------|
| `period` | `month\|quarter\|year\|custom` | `month` | Aggregation period |
| `start_date` | `date` | Start of current period | Custom period start (required if period=custom) |
| `end_date` | `date` | End of current period | Custom period end (required if period=custom) |
| `account_id` | `UUID` | — | Filter to single account |
| `category_id` | `UUID` | — | Filter to single category |
| `type` | `income\|expense` | — | Filter by transaction type |

**Response:**
```json
{
  "data": {
    "total_income": 1250000,
    "total_expenses": 890000,
    "net_flow": 360000,
    "transaction_count": 47,
    "currency": "EGP",
    "period": {
      "start": "2026-04-01",
      "end": "2026-04-30"
    }
  }
}
```

**Implementation:**
- Service function: `get_transaction_summary(session, household_id, filters)` in `services/transaction.py`
- Aggregation via SQLAlchemy: `func.sum(case(...))` for income/expenses in a single query
- Income = sum of positive `amount_minor`, expenses = sum of negative `amount_minor` (absolute value)
- `net_flow = total_income - total_expenses`
- Filter by `is_active = TRUE` and `household_id`
- Period resolution: `month` = calendar month, `quarter` = 3 months, `year` = 12 months, `custom` = explicit dates
- Router: add to existing `routers/transactions.py`

**Multi-currency note:** This endpoint returns totals in a single currency. For households with multi-currency accounts, the initial implementation aggregates only transactions matching the household's primary currency. Multi-currency aggregation with FX conversion is deferred to Phase 4 (BL-016).

### 1C — Account & Transaction Response Enrichment

#### BL-006: Account Balance History

**New endpoint:** `GET /api/v1/accounts/{id}/balance-history?period=month`

Returns current balance compared to start-of-period balance for the trend indicator.

**Response:**
```json
{
  "data": {
    "current_balance": 1250000,
    "period_start_balance": 1100000,
    "change": 150000,
    "change_direction": "up",
    "period": {
      "start": "2026-04-01",
      "end": "2026-04-04"
    }
  }
}
```

**Implementation:**
- Compute `period_start_balance` by taking current balance and subtracting all transaction deltas within the period
- Single query: `SELECT COALESCE(SUM(amount_minor), 0) FROM transactions WHERE account_id = ? AND date >= period_start AND is_active = TRUE`
- `period_start_balance = current_balance - period_sum`
- `change = current_balance - period_start_balance`
- `change_direction = "up" | "down" | "unchanged"`
- Add to `routers/accounts.py`

#### BL-007: Last Transaction Date in AccountResponse

**Modified:** `schemas/account.py` — add `last_transaction_date: date | None` to `AccountResponse`

**Implementation:**
- In `list_accounts` service, add a subquery or joined aggregation: `SELECT MAX(date) FROM transactions WHERE account_id = ? AND is_active = TRUE`
- Batch this across all accounts to avoid N+1 (use a single query with GROUP BY account_id)
- Returns `None` for accounts with no transactions

#### BL-008: Last Used Account

**New endpoint:** `GET /api/v1/transactions/last-used-account`

**Response:**
```json
{
  "data": {
    "account_id": "uuid-here"
  }
}
```

**Implementation:**
- Query: `SELECT account_id FROM transactions WHERE household_id = ? AND is_active = TRUE ORDER BY created_at DESC LIMIT 1`
- Returns 404 if no transactions exist
- Add to `routers/transactions.py`

#### BL-047: Debt ID in Transaction Response

**Modified:** `schemas/transaction.py` — add `debt_id: UUID | None` to `TransactionResponse`

**Implementation:**
- Join `debt_payments` table on `transaction_id` to get `debt_id`
- Use an outer join in the transaction list query to avoid N+1
- `debt_id` is `None` for transactions not linked to any debt

## 6. Frontend — Search & Refactoring

### Unit 6A — Command Palette

**New component:** `components/shared/command-palette.tsx`

Global search triggered by `Cmd+K` (Mac) / `Ctrl+K` (Windows).

**Implementation:**
- Add shadcn command component: `pnpm dlx shadcn@latest add -y command`
- Register global keyboard shortcut in the AppShell
- Search categories: Pages (static list), Accounts, Transactions (by description/merchant), Debts
- Use TanStack Query cached data for instant client-side filtering
- Show categorized results with icons
- Navigate on selection (router.push)
- Show keyboard shortcut hint in the navbar (subtle "Ctrl+K" badge)

**Search result structure:**
```tsx

  type: "page" | "account" | "transaction" | "debt";
  title: string;
  subtitle?: string;
  href: string;
  icon: LucideIcon;
```

**Limits:** Max 5 results per category, max 20 total. No backend search endpoint needed — this is purely client-side over cached data.
