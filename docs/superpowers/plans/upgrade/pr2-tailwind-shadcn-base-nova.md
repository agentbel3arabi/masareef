# Tailwind v4 + shadcn base-nova Migration — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Migrate the frontend from Tailwind CSS v3 + shadcn new-york (Radix UI) to Tailwind CSS v4 + shadcn base-nova (@base-ui/react), preserving all Masareef brand tokens and RTL logical property correctness.

**Architecture:** Three-stage migration — (1) Tailwind v4 infrastructure swap, (2) shadcn base-nova component regeneration, (3) RTL audit + token re-application. Each stage is verified independently before proceeding. Masareef brand tokens (applied in Unit 1I) must be captured before migration starts and re-applied after shadcn regenerates the CSS.

**Tech Stack:** Tailwind CSS v4, `@tailwindcss/postcss`, shadcn base-nova (`@base-ui/react`), Next.js 16, pnpm

**Prerequisites:**
- PR 1 (Next.js 16) merged and UAT 2 approved
- Unit 1I merged (Masareef brand tokens are in `globals.css`)

**Design spec:** `docs/superpowers/specs/2026-03-28-post-phase1-upgrade-design.md`

**Files:**
- Modify: `frontend/postcss.config.mjs`

- [ ] **Step 1: Replace the PostCSS plugin list**

  Current content:
  ```js
  const config = {
    plugins: {
      tailwindcss: {},
      autoprefixer: {},
    },
  };
  export default config;
  ```

  Replace with:
  ```js
  const config = {
    plugins: {
      '@tailwindcss/postcss': {},
    },
  };
  export default config;
  ```

  Tailwind v4 handles vendor prefixing internally — `autoprefixer` is no longer needed.

### Task 4: Migrate globals.css to Tailwind v4 syntax

**Files:**

- [ ] **Step 2: Delete `tailwind.config.ts`**

  ```bash
  rm frontend/tailwind.config.ts
  ```

  Tailwind v4 reads all config from CSS (`@theme {}` block) — the TypeScript config file is not used.

- [ ] **Step 3: Check `tailwindcss-animate` compatibility**

  In Tailwind v4, animation utilities (`animate-*`) are built-in. Check if `tailwindcss-animate` has a v4-compatible release:

  ```bash
  pnpm info tailwindcss-animate
  ```

  Look at the `peerDependencies` for the latest version. If it lists `tailwindcss: ^4`, it's compatible — keep it.
  If it only lists `tailwindcss: ^3`, remove it (Tailwind v4's built-in `animate-*` classes replace it):

  ```bash
  cd frontend && pnpm remove tailwindcss-animate
  ```

  Then remove the import from the (now deleted) `tailwind.config.ts` — no action needed since the file is already deleted.
  Search for any direct usage in source:

  ```bash
  grep -r "tailwindcss-animate" frontend/src/ || echo "no direct usage"
  ```

  Expected: `no direct usage` (it was only imported in `tailwind.config.ts`).

- [ ] **Step 4: Verify Tailwind v4 builds**

  ```bash
  cd frontend && pnpm build
  ```

  Expected: build succeeds. If you see "Cannot find module 'tailwindcss'" or PostCSS errors, verify `@tailwindcss/postcss` is installed and `postcss.config.mjs` uses `'@tailwindcss/postcss'` as the key (not `'tailwindcss'`).

- [ ] **Step 5: Commit the Tailwind v4 infrastructure**

  ```bash

  git rm frontend/tailwind.config.ts
  git commit -m "chore(frontend): migrate Tailwind v3 → v4, remove tailwind.config.ts"
  ```

### Task 6: Re-apply Masareef brand tokens

**Files:**
- Modify: `frontend/src/app/globals.css`

shadcn init replaced the CSS variable values with its own defaults. Now re-apply the Masareef brand values you captured in Task 1.

- [ ] **Step 1: Open the backup and new globals.css side by side**

  ```bash
  cat /tmp/masareef-tokens-backup.css
  cat frontend/src/app/globals.css
  ```

- [ ] **Step 2: Map each Masareef HSL value to oklch**

  The backup uses HSL format (e.g., `--primary: 221 83% 53%`). Tailwind v4 uses oklch.
  Convert using this formula: HSL `H S% L%` → oklch can be estimated with a conversion tool, but the simplest approach for each token is:

  **Recommended path — keep HSL format:** Tailwind v4 CSS variables accept any valid CSS color value. Write the Masareef values as-is using `hsl()`:
  ```css
  --primary: hsl(221 83% 53%);
  ```
  This avoids error-prone manual oklch conversion and produces identical visual output. Only convert to oklch if a future design audit specifically requires it.

- [ ] **Step 3: Replace the generated default neutral values with Masareef brand values in `globals.css`**

  Edit the `:root {}` and `.dark {}` blocks, replacing the shadcn defaults with the Masareef values from the backup.

### Task 8: RTL audit — fix physical directional classes in all regenerated components

**Files:**
- Modify: any file in `frontend/src/components/ui/` containing physical CSS classes

base-nova components are generated without RTL awareness. Every physical directional class must be converted to a logical equivalent.

- [ ] **Step 1: Find all physical directional classes in the UI component directory**

  ```bash
  grep -rn "\bpl-\|\bpr-\|\bml-\|\bmr-\|\bleft-\|\bright-\|\btext-left\|\btext-right" \
    frontend/src/components/ui/ || echo "none found"
  ```

  Record every match — file name, line number, class name.

- [ ] **Step 2: Apply the conversion rules to each match**

  | Physical class | Logical replacement |
  |----------------|-------------------|
  | `pl-{n}` | `ps-{n}` |
  | `pr-{n}` | `pe-{n}` |
  | `ml-{n}` | `ms-{n}` |
  | `mr-{n}` | `me-{n}` |
  | `left-{n}` | `start-{n}` |
  | `right-{n}` | `end-{n}` |
  | `text-left` | `text-start` |
  | `text-right` | `text-end` |
  | `border-l-{n}` | `border-s-{n}` |
  | `border-r-{n}` | `border-e-{n}` |
  | `rounded-l-{n}` | `rounded-s-{n}` |
  | `rounded-r-{n}` | `rounded-e-{n}` |

  Edit each file with the appropriate replacements.

- [ ] **Step 3: Re-run the grep to confirm zero remaining physical classes**

  ```bash
  grep -rn "\bpl-\|\bpr-\|\bml-\|\bmr-\|\bleft-\|\bright-\|\btext-left\|\btext-right" \
    frontend/src/components/ui/ || echo "none found"
  ```

  Expected: `none found`

- [ ] **Step 4: Commit RTL fixes**

  ```bash
  git add frontend/src/components/ui/
  git commit -m "chore(frontend): convert physical CSS classes to logical equivalents in base-nova components"
  ```
