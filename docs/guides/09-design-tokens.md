# Design Tokens & UI Reference

## Canonical Design Tokens

These values override any colors or fonts generated by Stitch. Always use these.

```
Primary green:    #16A34A  (emerald — income, CTA, positive actions)
Error red:        #EF4444  (expense, negative balance, destructive actions)
Warning amber:    #F59E0B  (warnings, due soon, budget ≥80% spent)

Light mode:
  Background:     #FFFFFF
  Surface:        #F8FAFC  (cards, sidebars, elevated panels)
  Card border:    #E2E8F0
  Text primary:   #0F172A
  Text secondary: #64748B

Dark mode:
  Background:     #0F172A
  Surface:        #1E293B
  Card border:    rgba(255, 255, 255, 0.08)
  Text primary:   #F8FAFC
  Text secondary: #94A3B8

Fonts:            Inter (Latin), Noto Sans Arabic (Arabic)
Border radius:    10px (cards, modals), 6px (inputs, buttons), 4px (badges, chips)
Default theme:    Light mode
```

### Semantic Color Usage

| Color | Use |
|-------|-----|
| `#16A34A` | Income amounts, positive net balance, success states, primary CTA buttons |
| `#EF4444` | Expense amounts, negative balance, destructive buttons, error messages |
| `#F59E0B` | Budget ≥80% spent, payment due within 7 days, warning toasts |
| `#64748B` | Secondary text, labels, placeholder text |
| `#E2E8F0` | Card borders, dividers, skeleton loaders |

## Component Library Reference

| Library | Purpose | Import |
|---------|---------|--------|
| **shadcn/ui** | UI component system (buttons, cards, dialogs, tables, forms) | `@/components/ui/` |
| **Lucide** | Icon set | `lucide-react` |
| **Plotly** | Charts (net worth trend, income/expense bar, category donut, cash flow) | `react-plotly.js` |
| **next-intl** | i18n + RTL support | `next-intl` |
| **TanStack Query** | Server state, caching, optimistic updates | `@tanstack/react-query` |

**RTL Support:** Set `dir="rtl"` on `<html>` for Arabic locale. All layout uses Tailwind's `rtl:` variant prefix. Never hardcode `left`/`right` — use `start`/`end` (logical properties).

## Usage Rules

> **These designs are layout references, not pixel-perfect specs.**

- Use them for layout structure, component hierarchy, and content placement
- **Do NOT copy colors or logo directly** — use the canonical tokens above
- **Do NOT copy font values** — Stitch may use different fonts; always use Inter + Noto Sans Arabic
- When building a screen: read the HTML file for layout guidance, then read the matching feature spec for exact content and behavior
- Stitch may generate slightly different color values or placeholder logos — always override with canonical values
