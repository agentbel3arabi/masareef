# Frontend Code Review Report

## Summary

The frontend codebase is in good overall health. Strict TypeScript is consistently applied with no `any` type usage. All toast notifications correctly use **sonner**. The Tailwind configuration is properly CSS-first (`@theme inline` in `globals.css`). No `dangerouslySetInnerHTML` usage exists. No secrets or API keys are hardcoded. TanStack Query is used correctly with proper cache invalidation. The `render` prop pattern (base-nova/@base-ui/react) is used throughout with no banned `asChild` occurrences.

Three actionable violations were found and fixed as part of this review:
1. Physical directional animation classes in an auto-generated shadcn component.
2. Two hardcoded hex colours that should use CSS design tokens.

_No critical findings._

### Warning

- **`frontend/src/components/ui/dropdown-menu.tsx:44`** — Physical directional Tailwind animation modifiers `data-[side=left]:slide-in-from-right-2` and `data-[side=right]:slide-in-from-left-2` are present alongside the correct logical counterparts (`data-[side=inline-start]:…`, `data-[side=inline-end]:…`). The physical variants are auto-generated by the shadcn CLI and would cause incorrect enter-animations when `@base-ui/react` emits an `inline-start` or `inline-end` side value in an RTL layout. **Fixed:** replaced with `data-[side=inline-start]:slide-in-from-end-2` and `data-[side=inline-end]:slide-in-from-start-2`; duplicate physical variants removed.

- **`frontend/src/components/ui/dropdown-menu.tsx:138`** — `DropdownMenuSubContent` had only physical `data-[side=left]` and `data-[side=right]` animation classes (no logical equivalents), breaking sub-menu animations in RTL mode. **Fixed:** replaced with `data-[side=inline-start]:slide-in-from-end-2` and `data-[side=inline-end]:slide-in-from-start-2`.

- **`frontend/src/components/layout/app-shell.tsx:14`** — `bg-[#f7f9fb]` is a hardcoded hex colour that bypasses the design-token system and will not respond to theme changes. The `--surface` token (HSL `210 40% 98%`) is the correct semantic match. **Fixed:** replaced with `bg-surface`.

- **`frontend/src/app/(auth)/layout.tsx:22`** — `bg-[#0F172A]` is a hardcoded hex value equivalent to Tailwind's `slate-950`. Hardcoded hex values bypass the token layer and block future theme updates. **Fixed:** replaced with `bg-slate-950`.

### Suggestion

- **`frontend/src/components/accounts/account-card.tsx`** (632 lines) — This file violates the single-responsibility principle by defining five distinct card types (`CreditAccountCard`, `BankAccountCard`, `CashAccountCard`, `DigitalAccountCard`, `FinancingAccountCard`) plus an edit/delete dialog. Recommend splitting each card variant into its own file under `components/accounts/cards/` and extracting the shared edit/delete dialog into `components/accounts/account-edit-dialog.tsx`.

- **`frontend/src/app/(app)/transactions/page.tsx:282`**, **`transfers/page.tsx:271`**, **`accounts/page.tsx:226`** — The bulk-selection and toolbar-action pattern (state, `useEffect` calling `setActions`, select-all/deselect-all handlers) is duplicated across three pages. Recommend extracting a `useBulkSelection<T>` hook and a shared `BulkActionToolbar` component.

- **`frontend/src/app/(auth)/login/page.tsx:125–128`** and **`signup/page.tsx:333–336`** — Google OAuth SVG paths use hardcoded brand hex values (`#4285F4`, `#34A853`, `#FBBC05`, `#EA4335`). These are required by the Google Sign-In brand guidelines and intentionally cannot be replaced with design tokens, but they should be extracted into a single shared `<GoogleLogo />` component to avoid duplication between the two auth pages.

- **`frontend/src/components/transactions/transaction-row.tsx`** (344 lines) — The inline edit dialog occupies ~120 lines inside an already large row component. Consider extracting `TransactionEditDialog` into its own file to keep `TransactionRow` under 200 lines.

- **Missing `Suspense` boundaries** — No `<Suspense>` wrappers exist around server components. The current architecture relies entirely on manual `isLoading` states in client components, which is consistent but means slow network fetches block the entire page render. For future server-component migrations, add `<Suspense fallback={<Skeleton />}>` at page boundaries and around expensive async segments.

- **`frontend/src/app/(app)/transactions/page.tsx`** and **`transfers/page.tsx`** — TanStack Query cache keys for filtered queries embed mutable filter objects directly (e.g., `["transactions", filters]`). Ensure filter objects are stable references (memoised) or serialised to avoid unnecessary cache misses on re-render.
